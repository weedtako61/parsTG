# parsTG — Telegram Digest

Юзербот на **Python 3.10+** и Telethon: по команде из собственного чата «Избранное» собирает новые публикации из публичных Telegram-каналов, фильтрует их и отправляет JSON-файлы обратно в «Избранное».

> **Безопасность:** файл `.session` даёт полный доступ к аккаунту Telegram. Не публикуйте его, не пересылайте и не добавляйте в Git. Не запускайте одну и ту же сессию одновременно на нескольких машинах.

## Возможности

- `/digest` — новые посты после сохранённых `last_id`; для канала без состояния используется первое окно в 24 часа. Максимальная глубина — 48 часов.
- `/digest today` — публикации с полуночи по Москве.
- `/digest 24h` — публикации за последние 24 часа.
- `/digest test` — первые три канала за последние 24 часа.
- Пауза между каналами, ограничение глубины просмотра и числа публикаций.
- Объединение альбомов, извлечение текста опросов, фильтр рекламы и дедупликация.
- JSON в UTF-8 с датами `Europe/Moscow` и ссылками на источники.
- Состояние обновляется только в обычном режиме и после успешной отправки всех частей JSON.

## Файлы

| Файл | Назначение |
|---|---|
| `digest.py` | Основной скрипт и обработчик команд |
| `config.py` | Каналы и параметры сбора |
| `.env.example` | Шаблон секретов |
| `requirements.txt` | Зависимости |

Локально дополнительно появятся `.env`, `telegram_digest.session`, `state.json`, `channels_cache.json`, каталог `output/` и `logs/`. Эти файлы не нужно коммитить.

## 1. Получение API_ID и API_HASH

1. Откройте [my.telegram.org](https://my.telegram.org).
2. Войдите по номеру телефона.
3. Перейдите в **API development tools** и создайте приложение.
4. Скопируйте `api_id` и `api_hash`.

Это API-данные вашего приложения Telegram, а не токен бота от BotFather.

## 2. Установка

Нужен Python 3.10 или новее. Рекомендуется создать виртуальное окружение.

### Windows (PowerShell)

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и замените примерные значения на свои `API_ID` и `API_HASH`. Не добавляйте реальные секреты в Git.

## 3. Настройка каналов

Откройте `config.py` и замените примеры в `CHANNELS` своими публичными каналами:

```python
CHANNELS = [
    "@channel_one",
    "https://t.me/channel_two",
    "channel_three",
]
```

Поддерживаются записи с `@`, без `@` и ссылки `https://t.me/...`; пробелы и дубликаты нормализуются автоматически. Скрипт проверяет, что найденная сущность — именно broadcast-канал, а не группа или пользователь.

В `config.py` можно менять лимиты, рекламные маркеры и паузу между каналами. Временная зона фиксирована на `Europe/Moscow`.

## 4. Первый запуск и авторизация

```bash
python digest.py
```

При первом запуске Telethon интерактивно запросит номер телефона, код входа и пароль 2FA, если он включён. Авторизацию лучше впервые выполнить на личном компьютере. Если затем переносите процесс на сервер, переносите файл `.session` только защищённым способом и храните его с ограниченными правами.

После запуска скрипт остаётся работать и ждёт команду, отправленную **в «Избранное» с этого же аккаунта**.

## 5. Команды

Отправляйте команды обычным сообщением в «Избранное»:

| Команда | Что делает | Меняет `state.json` |
|---|---|---|
| `/digest test` | Первые 3 канала, последние 24 часа | Нет |
| `/digest today` | С 00:00 МСК до текущего момента | Нет |
| `/digest 24h` | Последние 24 часа | Нет |
| `/digest` | Новые сообщения относительно сохранённых ID | Да, после успешной отправки |

Начните с `/digest test`. Проверьте JSON, ссылки, альбомы и опросы. После этого используйте `/digest`.

## 6. Результаты

JSON-файлы отправляются в «Избранное» и временно записываются в `output/`. Если суммарный объём текста превышает лимит, создаются части вида:

- `digest_YYYY-MM-DD_HHMM.json`
- `digest_YYYY-MM-DD_HHMM_part1.json`
- `digest_YYYY-MM-DD_HHMM_part2.json`

В каждом файле находится JSON-массив объектов с ключами `channel`, `username`, `date`, `link`, `text`, `views`, `forwarded_from`, `has_media`, `truncated`.

Служебные данные:

- `state.json` — последний просмотренный ID по каналам;
- `channels_cache.json` — кеш сущностей Telegram;
- `logs/digest.log` — журнал работы без текстов публикаций.

Если отправка файла не удалась, локальный файл сохраняется, а состояние не продвигается. Если подходящих постов нет, JSON не создаётся и состояние не меняется.

## 7. Важные ограничения

- Сбор идёт последовательно, с паузой между каналами.
- За один запуск скрипт просматривает не более 300 сообщений и сохраняет не более 50 публикаций на канал. При достижении лимита сканирования более старые сообщения за этим пределом могут не попасть в последующие запуски, поскольку состояние продвигается по максимальному просмотренному ID.
- Для обычного режима действует жёсткая глубина 48 часов. Если скрипт не запускался дольше, более старые публикации не будут собраны.
- Telegram может ограничивать частоту запросов. Короткий FloodWait автоматически пережидается и повторяется один раз; более длительный отражается в отчёте.
- Скрипт работает от личного аккаунта и соблюдает ограничения Telegram. Не используйте его для обхода приватности или массового нежелательного сбора данных.

## Остановка

Нажмите `Ctrl+C` в терминале. Скрипт корректно отключит Telegram-клиент.
